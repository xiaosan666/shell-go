## 一、可行性结论

**可行，且技术风险低。** 关键点逐条核对结果：

| 要求 | 结论 | 说明 |
|---|---|---|
| 不装 Java/Node/Python | ✅ 满足 | `CGO_ENABLED=0` 纯静态编译，产物无动态库依赖，麒麟 V10（x86/ARM）可直接跑 |
| 单文件部署 | ✅ 满足 | 前端资源用 `go:embed` 打进二进制，无需 nginx、无需 node |
| 页面登录 + 配置账号密码 | ✅ 满足 | 账号密码来自启动参数或 `config.yaml`，密码以 bcrypt 哈希存储 |
| 全部 POST、参数在 body | ⚠️ 有条件满足 | 唯一冲突点是**实时终端通道**，见 §3 决策 D1 |
| 请求/响应加密（SM4 等） | ✅ 满足 | `tjfoc/gmsm` 提供 SM2/SM3/SM4，纯 Go；前端用 `sm-crypto`(JS) |
| 多窗口 + 高亮 + iTerm 风格 | ✅ 满足 | `xterm.js` + `creack/pty`，服务端真 PTY，支持 `cd`/`vim`/`top`/Tab 补全/256 色 |
| 依赖可获取 | ✅ 已验证 | 本机 `goproxy.cn` 可达、npm 可达；`gmsm v1.4.1` 已在本地模块缓存 |
| ARM 交叉编译 | ✅ 满足 | 纯 Go 无 cgo，`GOARCH=arm64` 一次编译即可 |

**建议技术栈**（刻意做小，降低维护成本）：

- 标准库 `net/http`（Go 1.22+ 路由）+ `gorilla/websocket` + `creack/pty` + `tjfoc/gmsm` + `golang.org/x/crypto/bcrypt` + `gopkg.in/yaml.v3`
- 前端：**无需构建的原生 ES Module + 本地 vendored xterm.js**（不走 Vue/Vite）
- 预计二进制体积 10~14 MB，常驻内存 20~40 MB，单机 20 个并发会话无压力

> 与 `mayfly-go` 的关系：只参考其**工程形态**（`go:embed` 静态资源、`build_release.sh` 多目标交叉编译、`config.yml.example`、systemd 部署习惯），不引入其 Gin/GORM/IOC 体系 —— 这个工具体量小，套那套架构是负担。

## 二、需求理解与隐含风险（请重点看这一段）

您描述的场景里有一个必须点明的安全事实：

> 这个工具本质上是**把一个能执行任意命令的 shell 暴露在网页上**。谁拿到网页账号，就等于拿到运行该二进制的那个 OS 用户的完整权限。

所以有几件事必须提前定，否则做出来是"能用但不敢用"：

1. **以什么身份运行**：以 `root` 运行 = 网页账号即 root。若你们正是需要 root 能力（因为没有 root 密码，只能靠部署通道把二进制推上去），那就**必须**用强密码 + 内网 IP 白名单 + HTTPS + 审计日志来补偿，并且默认**拒绝 root 运行**，需显式 `--allow-root` 才放行。
2. **加密的真实边界**：应用层 SM4 只能防"抓包直接看到命令明文"，防不了中间人替换密钥。若链路本身不可信，必须叠加 TLS。这点在 §4 有明确取舍。
3. **"全 POST"的代价**：严格只允许 POST，会让交互式终端体验明显下降（详见 §3）。需要在"合规感"和"像 iTerm"之间选一个平衡点。

## 三、核心设计选择

### D1（最关键）命令执行模型 —— 三选一

| 方案 | 实现 | 能力 | 体验 | 与"全 POST" |
|---|---|---|---|---|
| **A. 一次性执行** | 每条命令 `bash -lc "..."`，POST 流式回包 | 无状态、并发安全 | ❌ 不能 `cd` 持久、不能 `vim`/`top`、无 Tab 补全、无 TTY（`sudo`/`ssh` 交互会卡住） | ✅ 完全符合 |
| **B. 持久 PTY + WebSocket** | 每窗口一个 `bash` + pty，双向实时流 | 完整交互能力 | ✅ 几乎等同本地 iTerm | ❌ WS 不是 POST |
| **C. 持久 PTY + POST 轮询** | 同上，但输入/输出走 `POST /input`、`POST /poll`（100ms 长轮询） | 完整交互能力 | ⚠️ 可用，但有 100~200ms 手感延迟，`vim` 光标移动发涩 | ✅ 符合（纯 POST） |

**我的建议：B 为准 + C 为降级开关**（配置 `transport: ws | poll`）。
理由：终端类工具的价值 90% 在交互体验，`cd`/`vim`/`top`/补全缺一不可；同时保留 `poll` 模式，若你们的安全扫描或 WAF 禁止 WebSocket，改一行配置即可切过去，功能不缩水、只牺牲手感。

> 若坚持"绝对不允许 WS"，我建议直接选 C，而**不要**选 A —— A 模式做出来会被用户骂"这不是 shell"。

### D2 多窗口形态

- 标签页（Tab）：✅ 必做，支持重命名、拖拽排序、中键关闭、`Ctrl+Tab` 切换
- 分屏（左右/上下最多 4 格）：建议做，但可放二期
- 断线/刷新恢复：会话在服务端保活（默认 30 分钟空闲回收），刷新页面可重连到原会话继续看历史滚动区

### D3 终端体验清单（对齐 iTerm 习惯）

必备：CJK 等宽字体回退（Noto Sans Mono CJK / 文泉驿）、256 色 + 真彩色、字号缩放 `Ctrl +/-`、主题（暗色/亮色，默认暗色）、`Ctrl+Shift+C/V` 与右键粘贴、`Ctrl+F` 搜索、URL 自动识别、滚动缓冲 10000 行、窗口 resize 同步 `winsize`、中文输入法（IME）正常上屏。

## 四、加密与认证方案

### 4.1 三层结构

```
[浏览器] --①握手取 SM2 公钥--> [服务端]
[浏览器] --②SM2 加密会话密钥 + SM4 密文登录--> [服务端] 校验 bcrypt 密码
[浏览器] <--③SM4 密文 token-- [服务端]
[浏览器] --④每个请求体: base64( IV | SM4-CBC 密文 | SM3-HMAC ) --> [服务端]
```

- **SM2**：仅用于交换会话密钥（服务端启动时生成密钥对，内存持有；重启用新密钥）
- **SM4-CBC + PKCS#7**：报文加密（16 字节随机 IV 随包）
- **SM3-HMAC**：完整性校验（前端 `sm-crypto` 不支持 SM4-GCM，故用 encrypt-then-MAC）
- **防重放**：包体带 `ts`（±60s 窗口）+ `nonce`（服务端 LRU 去重）

### 4.2 三档安全强度，请选一档

| 档位 | 组成 | 抗窃听 | 抗中间人 | 复杂度 |
|---|---|---|---|---|
| S1 | 前端硬编码 SM4 固定密钥 | 弱（仅防肉眼） | ❌ | 最低 |
| S2 | SM2 协商 + SM4/SM3（推荐） | ✅ | ⚠️ 无证书校验，可被替换公钥 | 中 |
| S3 | S2 + 自签 TLS（可配证书，默认自动生成） | ✅ | ✅（首次信任后） | 中，需用户点"继续访问" |

**建议 S2 为默认，S3 可开关。** 内网场景自签证书通常可接受，但会给非技术同事增加一次点击。

### 4.3 认证与会话

- 单账号（配置化），密码 bcrypt；支持 `--password-hash` 传入避免明文进命令行
- 会话 token：32 字节随机，服务端内存表，**放在 POST body**（不依赖 Cookie，符合"参数全在 body"）
- 空闲超时（默认 30min）、绝对超时（默认 12h）、并发会话上限（默认 5）
- 登录失败 5 次锁定 10 分钟（按 IP + 全局双计数）

## 七、确认结论（2026-11-09）

| # | 结论 |
|---|---|
| Q1 | 采用 **B + C 可切换**：默认 WebSocket，`terminal.transport: poll` 可降级为纯 POST 轮询 |
| Q2 | 采用 **S2**：SM2 协商 + SM4-CBC + SM3-HMAC；TLS 作为可开关项保留 |
| Q3 | **免构建**：xterm.js / sm-crypto 以 vendor 入库，编译机只需 Go |
| Q4 | **专用用户降权**：使用者只有普通用户权限，不需要 root，也未配置 sudo 白名单 |
| Q5 | `0.0.0.0:8443` + IP 白名单（可改 `127.0.0.1` 走反代） |
| Q6 | 审计记录登录/登出/终端开关/WS 连接；命令级与录屏回放列入后续版本 |
| Q7 | 标签页必做，分屏列入后续版本 |
| Q8 | 文件上传下载列入后续版本 |
| Q9 | 不做「网页内再 ssh 跳转」，只提供本机 shell |
| Q10 | 支持多用户各自独立会话 |
| Q11 | 浏览器基线 **Chrome 100+**，无需兼容 IE 与老内核 |
| Q12 | 默认端口 `8443`、服务名 `shell-go`、安装目录 `~/shell-go` |

由此产生的两处调整：

1. 因使用者只有普通用户权限，程序不再提权、不写 `/etc`，安装脚本改为注册 **systemd 用户服务**，
   开机自启需 `loginctl enable-linger $USER`；无 systemd 时退化为 `ctl.sh` 后台进程。
2. 浏览器基线提高后，前端直接使用原生 ES Module、`fetch`、WebSocket，不引入任何 polyfill 或构建链。

## 九、已知限制（提前说清，避免预期落差）

1. **应用层国密无法替代 TLS**：S2 档位在无 TLS 时，中间人仍可替换 SM2 公钥做全量解密。这是协议层限制，不是实现问题。
2. **前端加密不等于前端可信**：密钥在浏览器内存中，本机被控则无法防御。
3. **`sudo` 交互**：PTY 模式下可正常输密码；一次性执行模式会卡死 —— 这也是推荐 PTY 的原因之一。
4. **超大输出**（如 `cat` 一个 2GB 日志）：需分块 + 背压 + 前端丢弃策略，否则会打爆浏览器内存。我会默认开启输出限流（可配）。
5. **CJK 宽字符**：极少数命令输出的对齐会因字体度量差异略有偏差，属 xterm.js 通病，可通过固定字体缓解。
6. **麒麟安全加固**：若系统启用 SELinux 严格策略或 `/tmp` noexec，安装路径需避开 `/tmp`；`install.sh` 会检测并提示。

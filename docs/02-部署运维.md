# 部署与运维

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | 麒麟 V10（x86_64 / aarch64）、CentOS 7+、Ubuntu 18.04+ 等 |
| 架构 | `amd64`、`arm64` |
| 权限 | **普通用户**即可，不需要 root |
| 依赖 | 无。不需要 Java / Node / Python / glibc 特定版本 |
| 端口 | 默认 8443，可配置 |
| Shell | `/bin/bash`（默认），可改为 `/bin/zsh` 等 |

检查目标架构：

```bash
uname -m       # x86_64 → 用 linux-amd64；aarch64 → 用 linux-arm64
```

## 2. 安装

**用普通用户安装，不要用 root。** 程序默认拒绝以 root 身份运行——网页上暴露的是一个可执行任意
命令的 shell，以 root 跑等于把整机交给任何拿到网页账号的人。脚本检测到 root 会直接停下并给出
普通用户的安装命令。

```bash
tar xzf shell-go-1.5.0-linux-amd64.tar.gz
cd shell-go-1.5.0-linux-amd64

# 安装到 ~/shell-go，端口 8443，自动生成随机密码
./install.sh --port 8443

# 自定义安装目录、端口、监听地址（配置随之到 /data/apps/shell-go/config.yaml）
./install.sh --dir /data/apps/shell-go --port 9443 --bind 10.0.0.12

# 复用已有配置文件（不生成、不覆盖；--port/--bind 随之失效）
./install.sh --config /etc/shell-go.yaml

# 两者可组合：程序装到 --dir，配置读 --config 指的那份
./install.sh --dir /data/apps/shell-go --config /etc/shell-go.yaml

# 只放文件，不注册服务也不启动
./install.sh --no-service

# 允许程序以 root 运行（仅限隔离测试机；会把 security.allow_root 写成 true）
./install.sh --allow-root
```

`--allow-root` 与 `--dir` / `--config` 可任意组合。它对**新建和复用已有配置一样生效**：
配置里已有 `allow_root` 就改值，没有这一项就插到 `security:` 段首行，整个 `security:` 段都缺
则在文件末尾补一段。升级场景（配置是上次装的、这次只换版本）千万别漏这个参数，
否则脚本注册完服务、端口却不监听——`Restart=on-failure` 每 3 秒拉起一次，
`data/stdout.log` 里会反复出现同一段 `[错误] 检测到以 root 身份运行`。

### 配置文件的位置由谁决定

安装时决定，启动时由脚本引用，正常使用不需要手工传 `-config`：

- 默认 `$INSTALL_DIR/config.yaml`（即 `~/shell-go/config.yaml`）
- `--dir X` → 配置随安装目录到 `X/config.yaml`
- `--config Y` → 直接用 `Y`，脚本不生成、不改写；`Y` 不存在时直接报错退出

最终路径被写入 systemd unit 的 `ExecStart=%h/shell-go/shell-go -config <你的路径>`
（装在 `$HOME` 外时整段替换为绝对路径）以及 `ctl.sh` 的 `nohup … -config <你的路径>`。
所以 `systemctl --user restart shell-go` 与 `ctl.sh restart` 用的都是同一份配置。

复用已有配置时的两个注意点：

- **不打印密码**：密码以你文件里的 `password_hash` 为准
- **`--port` / `--bind` 不生效**：监听地址取配置文件里的 `listen`，脚本自检端口和显示的访问地址都以它为准

如果绕开脚本直接运行二进制，查找顺序是：`-config <path>` → 环境变量 `SHELLGO_CONFIG` →
当前目录 `./config.yaml` → 都没有则用内置默认值（`0.0.0.0:8443`，无账号，等于不可用）。

安装脚本行为：

1. 复制二进制与配置到安装目录，创建 `data/` 目录（其中 `data/records/` 存放会话录制）
2. 生成 `config.yaml`（密码以 bcrypt 哈希写入，权限 600），**终端会打印一次明文密码**
3. 优先注册 `systemd --user` 服务；不可用时生成 `ctl.sh` 并后台启动
4. **自检端口是否真的在监听**：起不来就打印日志末尾与排查顺序，并以非零码退出

安装目录默认是 `~/shell-go`，与解压目录无关：解压目录名带版本号，升级时会变，而 systemd 服务里
的路径是写死的。装到固定目录后，解压目录可以直接删。

升级：解压新版、再跑一次 `./install.sh`。检测到已有 `config.yaml` 会保留，不会覆盖密码。

验证：

```bash
curl -s -X POST http://127.0.0.1:8443/api/handshake -d '{}' -H 'Content-Type: application/json'
# 返回 {"sid":"...","pub":"04...","alg":"SM2/SM4-CBC/SM3-HMAC",...} 即为正常
```

服务没起来时按顺序查：

```bash
~/shell-go/ctl.sh status                            # 或 systemctl --user status shell-go
tail -n 50 ~/shell-go/data/stdout.log
~/shell-go/shell-go -config ~/shell-go/config.yaml   # 前台跑一次，直接看报错
ss -lntp | grep 8443                                # 端口是否被别的进程占用
```

## 3. 服务管理

### systemd 用户服务

```bash
systemctl --user status shell-go
systemctl --user restart shell-go
systemctl --user stop shell-go
journalctl --user -u shell-go -f
```

用户级服务在用户未登录时不会自动启动，需要开启 linger：

```bash
loginctl enable-linger $USER
```

### ctl.sh（无 systemd 时）

```bash
~/shell-go/ctl.sh start|stop|restart|status
```

### 直接前台运行

```bash
cd ~/shell-go
./shell-go -config config.yaml
```

启动日志会打印实际监听地址、传输模式与安全提醒。

## 4. 配置要点

完整字段见 README 的配置表。生产环境建议：

```yaml
listen: "0.0.0.0:8443"

tls:
  enabled: true       # 内网也建议开启，至少能防被动嗅探与部分中间人
  auto: true          # 自签证书，浏览器首次访问需信任

users:
  - username: ops
    password_hash: "$2a$10$..."   # 用 ./shell-go -gen-hash '密码' 生成

security:
  ip_whitelist:
    - 10.0.0.0/8
    - 192.168.10.0/24
  idle_timeout: 15m
  session_ttl: 8h
  max_sessions: 3
  max_terms: 6

terminal:
  transport: ws       # 被 WAF 拦截时改 poll
  idle_close: 20m

# 文件管理：只放开需要读写的目录，敏感环境可整体关闭
files:
  enabled: true
  root: "~"           # 文件管理的根目录（不是 Linux root 用户），或 /data/apps
  max_upload_mb: 100
  allow_write: true
  allow_delete: false # 只允许下载时关掉删除

# 会话录制：按磁盘容量设置上限
record:
  enabled: true
  dir: "data/records"
  max_mb: 50
  keep_days: 7
  max_files: 200
```

修改配置后 `systemctl --user restart shell-go` 生效。

## 5. 日志

| 文件 | 内容 | 轮转 |
|---|---|---|
| `data/server.log` | 运行日志（启动、错误、安全告警） | 无自动轮转，建议配 logrotate |
| `data/audit.log` | 审计事件（登录/登出/终端开关/WS 连接/文件操作/录制删除） | 20MB 自动轮转一份 `.1` |
| `data/records/*.jsonl` | 会话录制（终端输出时间轴），默认 0600 | 按 `record.keep_days` / `record.max_files` 启动时清理 |
| `data/stdout.log` | systemd 或 ctl.sh 的进程输出 | 同上 |

审计日志格式（每行一个 JSON）：

```json
{"time":"2026-11-09 18:03:21.412","event":"login","user":"admin","ip":"10.1.2.3"}
{"time":"2026-11-09 18:03:25.008","event":"term_open","user":"admin","ip":"10.1.2.3","term":"a1b2c3d4"}
```

`logrotate` 示例（放在 `~/.config/logrotate.d/` 或联系管理员）：

```
/home/ops/shell-go/data/*.log {
    weekly
    rotate 8
    compress
    missingok
    notifempty
    copytruncate
}
```

## 6. 升级

```bash
systemctl --user stop shell-go
cp shell-go ~/shell-go/shell-go.new
mv ~/shell-go/shell-go ~/shell-go/shell-go.bak
mv ~/shell-go/shell-go.new ~/shell-go/shell-go
chmod +x ~/shell-go/shell-go
systemctl --user start shell-go
./shell-go -version
```

升级会终止所有正在运行的终端会话，建议在维护窗口进行。
`config.yaml` 不会被覆盖，新增配置项会自动使用默认值。

## 7. 防火墙与端口

```bash
# firewalld
sudo firewall-cmd --permanent --add-port=8443/tcp
sudo firewall-cmd --reload

# 无 root 时，请让网络管理员开通对应策略
```

不要把端口直接暴露到办公网之外；如必须跨网段访问，务必启用 TLS 与 IP 白名单。

## 8. 性能基线

在 2 核 4G 的麒麟虚拟机上实测（本地回环、默认参数）：

| 场景 | 结果 |
|---|---|
| 二进制体积 | 约 12 MB |
| 常驻内存 | 单实例约 25~40 MB，每个终端约 1~3 MB |
| 首次加载 | 约 300 ms（内嵌资源，无外部请求） |
| 交互延迟 | 局域网 < 10 ms；轮询模式约 100~200 ms |
| 大输出 | `cat` 100MB 文件时自动分块，内存稳定，浏览器端表现取决于滚动缓冲 |

## 9. 排障

| 现象 | 排查方向 |
|---|---|
| 启动即退出，提示「检测到以 root 身份运行」 | 用普通用户启动，或显式 `-allow-root`（不建议） |
| 浏览器提示「请求已过期」 | 服务器与浏览器时间差超过 5 分钟，校时（`chronyd`/`ntpd`） |
| 登录后白屏 | 打开开发者工具看控制台；多为浏览器版本过低或 CSP 拦截 |
| 点击登录一直转圈 | 检查 `/api/handshake` 是否可达，反向代理是否改写了 `Host` |
| 终端无输出但连接正常 | 检查 `terminal.env` 中 `TERM` 是否为 `xterm-256color`；确认 shell 路径存在 |
| 中文显示为方块 | 安装 `wqy-microhei` / `wqy-zenhei` 字体 |
| `vim` 界面错乱 | 确认窗口未被压至极小；服务端会拒绝小于 20 列的 resize |
| WebSocket 立即断开 | 反代未透传 `Upgrade`/`Connection` 头，或安全设备拦截；可改 `transport: poll` |
| 端口被占用 | `ss -lntp \| grep 8443`，改 `listen` 或停掉占用进程 |
| 文件管理提示「路径超出允许范围」 | 检查 `files.root`，路径与符号链接都必须落在这个目录内 |
| 上传到一半失败 | 看 `data/server.log`；多为超过 `max_upload_mb` 或目标目录无写权限 |
| 会话列表为空 | 确认 `record.enabled`、`record.dir` 可写；空会话（无输出）不会留文件 |

## 10. 反向代理（可选）

若坚持只监听 `127.0.0.1`：

```nginx
location / {
    proxy_pass http://127.0.0.1:8443;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}
```

注意：程序默认**不信任** `X-Forwarded-For`，此时 IP 白名单与审计记录到的都是代理地址。
如需按真实客户端 IP 过滤，请让反代直连并保留 `RemoteAddr`，或后续版本启用 `trust_proxy`。

## 兼容性验证

发布前在真实 Linux 内核上跑过一遍，不只是交叉编译通过：

| 环境 | 方式 | 结果 |
|---|---|---|
| Debian 12 / x86_64（glibc 2.36） | 容器内以普通用户运行 amd64 静态二进制 | 启动、PTY、resize、中文、ANSI、vim、文件、录制回放全部正常 |
| macOS / arm64 | 本机直接运行 | 同上 |

验证项与命令：

- 二进制无动态依赖：`ldd ./shell-go` → `not a dynamic executable`
- 终端尺寸：`stty size` 随窗格变化（`SIGWINCH` 生效）
- 中文：`echo 中文测试` 原样回传，不依赖外部 locale 包
- 全屏程序：`vim` 可正常进入与退出
- 解包无警告：包内不含 macOS 扩展属性头

麒麟 V10 使用同一套 Linux PTY 与信号接口，行为一致；如遇差异，优先检查 `terminal.shell`
路径与 `LANG`（见下）。

### 关于 locale

程序不再写死 `LANG`，启动时按下面的顺序决定：

1. `terminal.env.LANG` 显式配置 → 用配置值
2. 继承 shell-go 进程自身的 `LANG`
3. 以上都没有 → 补 `C.UTF-8`

若目标机是纯 POSIX locale 且 `locale -a` 里没有 `C.UTF-8`（很老的 glibc），中文可能显示为问号，
此时把 `terminal.env.LANG` 设为机器上真实存在的 UTF-8 locale（如 `zh_CN.UTF-8`）。
